SGBD Relacional MySQL

TechAssist

Projeto de banco de dados relacional: modelagem, normalização, consultas SQL e relatórios.

1. Domínio e Contextualização do Negócio

O projeto contempla o domínio de gestão de assistência técnica de equipamentos de TI, utilizando o banco de dados tech_assist. A empresa fictícia TechAssist realiza manutenção em notebooks, computadores, celulares e impressoras.

Cenário sem um SGBD relacional

  • Cadastros duplicados e dados inconsistentes.
  • Falta de vínculo entre clientes e equipamentos.
  • Dificuldade para acompanhar técnicos e ordens de serviço.
  • Falta de controle sobre as peças em estoque.

Solução com MySQL e InnoDB

  • Integridade dos dados e relacionamentos entre tabelas.
  • Centralização do histórico de manutenção.
  • Consultas para acompanhar serviços e técnicos.
  • Relatórios para auxiliar o controle dos serviços e do estoque.

2. Modelagem Lógica do Banco de Dados

O banco de dados é composto por cinco tabelas, organizadas para armazenar clientes, equipamentos, técnicos, serviços e peças.

Tabela Campos / Atributos Tipos de dados principais Chaves e restrições
clientes id_cliente, cli_nome, cli_cpf, cli_email, cli_telefone INT, VARCHAR(100), CHAR(11), VARCHAR(100), VARCHAR(20) PK em id_cliente; CPF UNIQUE
equipamentos id_equipamento, id_cliente, equ_tipo, equ_marca, equ_modelo, equ_problema INT, VARCHAR(50), VARCHAR(100), TEXT PK em id_equipamento; FK em id_cliente
tecnicos id_tecnico, tec_nome, tec_especialidade INT, VARCHAR(100) PK em id_tecnico
servicos id_servico, id_equipamento, id_tecnico, ser_data_entrada, ser_data_saida, ser_status, ser_valor INT, DATETIME, VARCHAR(50), DECIMAL(10,2) PK em id_servico; FK em id_equipamento e id_tecnico
pecas id_peca, pec_nome, pec_quantidade, pec_preco INT, VARCHAR(100), DECIMAL(10,2) PK em id_peca

Relacionamentos e cardinalidades

  • clientes (1) → (N) equipamentos: um cliente pode cadastrar vários equipamentos.
  • equipamentos (1) → (N) serviços: um equipamento pode possuir vários serviços ao longo do tempo.
  • técnicos (1) → (N) serviços: um técnico pode ser responsável por vários serviços.

3. Aplicação das Formas Normais

A normalização organiza os dados para reduzir redundâncias e evitar problemas de inserção, atualização e exclusão.

1FN

Primeira Forma Normal

Cada campo armazena um valor atômico, sem grupos repetitivos na mesma coluna.

2FN

Segunda Forma Normal

Atende à 1FN e elimina dependências parciais em relação a chaves compostas.

3FN

Terceira Forma Normal

Atende à 2FN e evita dependências transitivas entre atributos não-chave.

4FN

Quarta Forma Normal

Evita dependências multivaloradas independentes que possam gerar redundância nos registros.

01. Consultas e Relacionamentos

01 Listagem completa dos serviços INNER JOIN · ORDER BY

Exibe os serviços, clientes, equipamentos, técnicos, status e valores, ordenados pelo ID. 

SELECT
    s.id_servico,
    c.cli_nome AS cliente,
    e.equ_tipo AS equipamento,
    e.equ_marca AS marca,
    e.equ_modelo AS modelo,
    t.tec_nome AS tecnico,
    s.ser_status AS status,
    s.ser_valor AS valor
FROM servicos s
INNER JOIN equipamentos e
    ON s.id_equipamento = e.id_equipamento
INNER JOIN clientes c
    ON e.id_cliente = c.id_cliente
INNER JOIN tecnicos t
    ON s.id_tecnico = t.id_tecnico
ORDER BY s.id_servico;
02 Serviços do cliente Nicolas WHERE · INNER JOIN · ORDER BY DESC

Filtra os serviços do cliente Nicolas e ordena pela data de entrada, da mais recente para a mais antiga. 

SELECT
    c.cli_nome AS cliente,
    e.equ_tipo AS equipamento,
    e.equ_modelo AS modelo,
    s.ser_status AS status,
    t.tec_nome AS tecnico,
    s.ser_valor AS valor
FROM clientes c
INNER JOIN equipamentos e
    ON c.id_cliente = e.id_cliente
INNER JOIN servicos s
    ON e.id_equipamento = s.id_equipamento
INNER JOIN tecnicos t
    ON s.id_tecnico = t.id_tecnico
WHERE c.cli_nome = 'Nicolas'
ORDER BY s.ser_data_entrada DESC;
06 Equipamentos por cliente INNER JOIN · ORDER BY

Lista os clientes e os dados dos seus equipamentos, em ordem alfabética pelo nome. 

SELECT
    c.cli_nome,
    e.equ_tipo,
    e.equ_marca,
    e.equ_modelo
FROM clientes c
INNER JOIN equipamentos e
    ON c.id_cliente = e.id_cliente
ORDER BY c.cli_nome;
07 Serviços e técnicos responsáveis INNER JOIN · ORDER BY

Mostra o ID de cada serviço, o técnico responsável, sua especialidade e o status do atendimento. 

SELECT
    s.id_servico,
    t.tec_nome,
    t.tec_especialidade,
    s.ser_status
FROM servicos s
INNER JOIN tecnicos t
    ON s.id_tecnico = t.id_tecnico
ORDER BY s.id_servico;

02. Relatórios por Técnico

03 Quantidade e valor por técnico COUNT · SUM · GROUP BY

Calcula a quantidade de serviços de cada técnico e soma os valores correspondentes. 

SELECT
    t.tec_nome AS tecnico,
    t.tec_especialidade AS especialidade,
    COUNT(s.id_servico) AS quantidade_servicos,
    SUM(s.ser_valor) AS valor_total
FROM tecnicos t
INNER JOIN servicos s
    ON t.id_tecnico = s.id_tecnico
GROUP BY
    t.id_tecnico,
    t.tec_nome,
    t.tec_especialidade
ORDER BY valor_total DESC;
04 Técnicos com mais de um serviço COUNT · AVG · HAVING

Identifica técnicos com mais de um serviço, exibindo a quantidade e o valor médio cobrado. 

SELECT
    t.tec_nome AS tecnico,
    COUNT(s.id_servico) AS quantidade_servicos,
    ROUND(AVG(s.ser_valor), 2) AS valor_medio
FROM tecnicos t
INNER JOIN servicos s
    ON t.id_tecnico = s.id_tecnico
GROUP BY
    t.id_tecnico,
    t.tec_nome
HAVING COUNT(s.id_servico) > 1
ORDER BY quantidade_servicos DESC;

03. Filtros e Situação dos Serviços

05 Serviços em andamento WHERE

Lista os serviços em andamento, com equipamento, status e valor. 

SELECT
    id_servico,
    id_equipamento,
    ser_status,
    ser_valor
FROM servicos
WHERE ser_status = 'Em andamento';
11 Notebooks com problemas específicos WHERE · LIKE · OR · INNER JOIN

Localiza notebooks com descrições de problemas que contenham "defeito" ou "Lentidao". 

SELECT
    c.cli_nome AS cliente,
    e.equ_marca AS marca,
    e.equ_modelo AS modelo,
    e.equ_problema AS problema,
    t.tec_nome AS tecnico,
    s.ser_status AS status
FROM clientes c
INNER JOIN equipamentos e
    ON c.id_cliente = e.id_cliente
INNER JOIN servicos s
    ON e.id_equipamento = s.id_equipamento
INNER JOIN tecnicos t
    ON s.id_tecnico = t.id_tecnico
WHERE e.equ_tipo = 'Notebook'
  AND (
      e.equ_problema LIKE '%defeito%'
      OR e.equ_problema LIKE '%Lentidao%'
  )
ORDER BY c.cli_nome;
13 Serviços acima de R$ 200,00 WHERE · ORDER BY DESC

Apresenta os serviços com valor superior a R$ 200,00, do mais caro para o mais barato. 

SELECT
    id_servico,
    ser_valor,
    ser_status
FROM servicos
WHERE ser_valor > 200
ORDER BY ser_valor DESC;
14 Quantidade de serviços por status COUNT · GROUP BY · ORDER BY

Conta os serviços de cada status, do mais frequente para o menos frequente. 

SELECT
    ser_status,
    COUNT(*) AS quantidade
FROM servicos
GROUP BY ser_status
ORDER BY quantidade DESC;
15 Serviços concluídos WHERE · ORDER BY ASC

Exibe o ID, a data de saída e o valor dos serviços concluídos, da conclusão mais antiga para a mais recente. 

SELECT
    id_servico,
    ser_data_saida,
    ser_valor
FROM servicos
WHERE ser_status = 'Concluido'
ORDER BY ser_data_saida ASC;

04. Indicadores e Agregações

08 Quantidade de equipamentos por cliente COUNT · GROUP BY

Conta os equipamentos de cada cliente, do maior número para o menor. 

SELECT
    c.cli_nome,
    COUNT(e.id_equipamento) AS quantidade_equipamentos
FROM clientes c
INNER JOIN equipamentos e
    ON c.id_cliente = e.id_cliente
GROUP BY
    c.id_cliente,
    c.cli_nome
ORDER BY quantidade_equipamentos DESC;
09 Valor total dos serviços SUM

Soma os valores de todos os serviços registrados, independentemente do status. 

SELECT
    SUM(ser_valor) AS valor_total_servicos
FROM servicos;
10 Valor médio dos serviços AVG · ROUND

Calcula a média dos valores registrados, arredondada para duas casas decimais. 

SELECT
    ROUND(AVG(ser_valor), 2) AS valor_medio
FROM servicos;
12 Valor total do estoque de peças SUM · Multiplicação

Multiplica a quantidade de cada peça pelo preço unitário e soma os resultados para estimar o valor do estoque. 

SELECT
    SUM(pec_quantidade * pec_preco) AS valor_total_estoque
FROM pecas;
